# Архітектура та дизайн API (API Design)

Цей документ описує основні принципи проєктування, архітектурні рішення та стандарти RESTful API для вебзастосунку «Рехаб».

## 1. Загальні принципи REST
* **Ресурсний підхід:** Усі сутності системи представлені у вигляді ресурсів з унікальними URI (наприклад, `/api/v1/users`, `/api/v1/records`).
* **HTTP-методи:** 
  * `GET` — отримання ресурсів або списків.
  * `POST` — створення нових ресурсів (наприклад, новий запис дня тверезості).
  * `PUT / PATCH` — оновлення існуючих ресурсів.
  * `DELETE` — видалення або скасування (наприклад, видалення запису чи цілі).
* **Стандартні HTTP-коди стану:**
  * `200 OK` — успішний запит.
  * `201 Created` — успішне створення ресурсу.
  * `400 Bad Request` — помилка валідації вхідних даних.
  * `401 Unauthorized` — відсутній або недійсний JWT-токен.
  * `403 Forbidden` — недостатньо прав доступу (наприклад, звичайний користувач намагається відкрити адмін-панель).
  * `404 Not Found` — ресурс не знайдено.

## 2. Версіонування API
* API використовує префікс у шляху для версіонування: **`/api/v1/`**. Це дозволяє безпечно впроваджувати нові зміни без порушення роботи чинних клієнтів.
