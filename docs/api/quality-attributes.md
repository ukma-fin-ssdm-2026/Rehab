    # Матриця атрибутів якості API (Quality Attributes)

    ## 1. Цілі якості

    | ID | Атрибут | Ціль | Умова провалу | Як забезпечуємо | Як перевіряємо |
    |---|---|---|---|---|---|
    | PERF-001 | Продуктивність | Редагування запису календаря дозволене тільки протягом 48 годин | Запис можна змінити після завершення дозволеного періоду | Перевірка часу перед оновленням запису | Запит PATCH до запису в межах і поза межами 48 годин |
    | SEC-001 | Безпека | Запити до адміністративної панелі, системи модерації скарг та статистики інших користувачів перевіряють JWT-токен і відповідну роль | Якщо захищений запит можна виконати без потрібної ролі | JWT та перевірка ролей на сервері | Перевірка запитів без токена, з неправильним токеном і з неправильною роллю |
    | SEC-002 | Безпека | 0 паролів зберігаються у відкритому вигляді | Якщо пароль зберігається без хешування | Хешування паролів перед збереженням у БД | Перевірка даних у базі та коду авторизації |
    | REL-001 | Надійність | Доступність системи не менше 99,5% на місяць | Якщо доступність падає нижче 99,5% | Моніторинг роботи сервера та автоматичне відновлення після помилок | Моніторинг доступності API та розрахунок фактичного uptime |
    | REL-002 | Надійність | Повторне створення запису на ту саму дату повертає HTTP 409 | API створює дублікат або повертає інший статус | Перевірка наявності запису перед створенням | Два POST-запити з однаковою датою |
    | API-001 | Узгодженість API | Помилки API повертаються в єдиному форматі | Відповідь не відповідає визначеній структурі помилки | ПСпільна обробка помилок | Перевірка тіла відповіді для 401, 404, 409 і 422 |

    ## 2. Аналіз компромісів

    | Атрибут | Компроміс | Вплив | Пом'якшення |
    |---|---|---|---|
    | Безпека / Продуктивність | Перевірка JWT може збільшувати час відповіді API | Невелике збільшення часу обробки запиту | Оптимізувати перевірку токенів без відмови від безпеки |
    | Надійність / Продуктивність | Додаткові перевірки можуть збільшувати час обробки | Можливе збільшення навантаження на API | Виконувати перевірки лише там, де вони необхідні |
    | Надійність / Продуктивність | Перевірка повторної дати додає додаткову операцію під час створення запису | Може трохи збільшити час відповіді | Використовувати перевірку унікальності запису |

    ## 3. Сценарії перевірки якості

    ### Сценарій 1 — Продуктивність

    - **Умова:** 100 користувачів одночасно надсилають запити до API.
    - **Очікуваний результат:** 95-й процентиль часу відповіді для оновлення календаря та завантаження статистики не перевищує 500 мс.
    - **Перевірка:** навантажувальне тестування API.

    ### Сценарій 2 — Безпека

    - **Умова:**  користувач намагається змінити запис календаря в межах дозволених 48 годин та після завершення цього періоду.
    - **Очікуваний результат:** API дозволяє редагування в межах 48 годин і відхиляє запит поза дозволеним періодом.
    - **Перевірка:** запити PATCH до записів із різним часом створення або датою, залежно від реалізації правила в коді.
    ### Сценарій 3 — Захист паролів

    - **Умова:** пароль користувача зберігається в системі.
    - **Очікуваний результат:** пароль не зберігається у відкритому вигляді.
    - **Перевірка:** аналіз коду авторизації та перевірка способу зберігання паролів у базі даних.

    ### Сценарій 4 — Надійність

    - **Умова:** API працює протягом контрольованого періоду.
    - **Очікуваний результат:** доступність системи становить не менше 99,5%.
    - **Перевірка:** моніторинг доступності та розрахунок uptime.

    ### Сценарій 5 — Зручність використання

    - **Умова:** користувач двічі створює запис календаря на одну дату.
    - **Очікуваний результат:** перший запит виконується успішно, повторний повертає HTTP 409 Conflict.
    - **Перевірка:** два POST-запити з однаковою датою через Swagger UI.

    ### Сценарій 6 — Єдиний формат помилок

    - **Умова:** користувач надсилає запит, який призводить до помилки.
    - **Очікуваний результат:** API повертає відповідний HTTP-статус і тіло помилки згідно із задокументованим форматом.
    - **Перевірка:** перегляд відповідей із кодами 401, 404, 409 та 422, порівняння структури відповідей.
