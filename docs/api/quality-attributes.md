# Матриця атрибутів якості API (Quality Attributes)

Цей документ визначає нефункціональні вимоги, метрики якості та умови їх провалу для RESTful API вебзастосунку «Рехаб».

## 1. Продуктивність (Performance)
* **Ціль:** Час відгуку для основних ендпоінтів (читання списків та створення записів днів) має бути мінімальним.
* **Метрика:** Середній час відповіді сервера (Average Response Time).
* **Умова провалу:** Ціль вважається невиконаною, якщо середній час відповіді сервера перевищує **500 мс** при стандартному навантаженні (до 50 одночасних запитів).

## 2. Надійність та доступність (Availability)
* **Ціль:** API повинен бути стабільним та доступним для мобільних та вебклієнтів.
* **Метрика:** Коефіцієнт успішних запитів (Uptime / Success Rate).
* **Умова провалу:** Ціль вважається невиконаною, якщо відсоток помилок сервера (код 5xx) перевищує **1%** від загальної кількості запитів за добу.

## 3. Безпека (Security)
* **Ціль:** Захист чутливих психологічних даних користувачів та їхніх статусів тверезості від несанкціонованого доступу.
* **Метрика:** Наявність та примусове використання токенів автентифікації.
* **Умова провалу:** Ціль вважається невиконаною, якщо хоча б один ендпоінт, що працює з персональними даними (`/api/v1/users`, `/api/v1/records`), дозволяє отримати доступ без дійсного JWT-токена.

## 4. Валідація та цілісність даних (Data Validation)
* **Ціль:** Запобігання потраплянню некоректних або шкідливих даних у базу даних.
* **Метрика:** Відсоток відхилених некоректних запитів на рівні бекенду.
* **Умова провалу:** Ціль вважається невиконаною, якщо сервер приймає запити з порожніми або невалідними обов'язковими полями (наприклад, створення запису без статусу тверезості) замість повернення помилки `400 Bad Request`.
