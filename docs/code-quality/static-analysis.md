# Статичний аналіз безпеки

## 1. Мета перевірки

Мета аналізу — виявити потенційні проблеми безпеки в Python-коді проєкту **Rehab**, зафіксувати результати автоматичної перевірки та розглянути ризик із наявної моделі загроз STRIDE.

## 2. Інструмент і охоплення

Для статичного аналізу використано **Bandit 1.9.4**.

**Команда запуску:**

```bash
python -m bandit -r src -f txt
```

| Виявлено потенційних проблем | 0 |

| Проблем середньої серйозності | 0 |
| Проблем низької серйозності | 0 |

**Результат Bandit:** `No issues identified.`

Відсутність знахідок означає, що Bandit не виявив проблем, які відповідають його правилам перевірки. Це не є доказом повної безпеки застосунку.

## 3. Аналіз потенційного ризику

### SEC-01 — Підробка особи через демонстраційний токен

| Атрибут | Значення |
|---|---|
| Категорія STRIDE | Spoofing — підробка особи |
| Файл | `src/api/security.py` |
| Метод виявлення | Ручний аналіз коду |
| Рівень ризику | Високий для продуктивного середовища |
| Ідентифікатор правила Bandit | Не застосовується |

**Опис**

Поточний механізм авторизації використовує демонстраційні токени у форматі `<роль>-<ідентифікатор>`, наприклад `admin-1`. Код перевіряє формат токена та допустимість ролі, але не перевіряє криптографічний підпис JWT і термін його дії.

У разі використання цієї реалізації в продуктивному середовищі клієнт потенційно може самостійно сформувати токен із привілейованою роллю та видати себе за іншого користувача.

**Рекомендовані заходи**

- Замінити демонстраційний токен на справжній JWT із перевіркою підпису та терміну дії.
- Перевіряти необхідні claims і права доступу на сервері.
- Додати автоматизовані тести на підроблені токени та спроби доступу з недостатніми правами.

**Поточний статус:** ризик задокументовано. Демонстраційний механізм залишається в прототипі та не повинен використовуватися як повноцінна продуктивна авторизація.

> цей ризик виявлено під час ручного аналізу `security.py`. Bandit його не повідомляв, тому він не є знахідкою автоматичного аналізатора.

## 4. Обмеження перевірки

Bandit перевіряє лише ті категорії проблем, для яких має відповідні правила. Результат із нульовою кількістю знахідок не виключає помилок авторизації, бізнес-логіки або контролю доступу.

Проведена перевірка не замінює тестування автентифікації, авторизації та перевірки прав доступу для окремих ендпоінтів.
