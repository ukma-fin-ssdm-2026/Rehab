## Пропозиції, які можна пояснити

1. Перед PR виконувати Black --check backend і зробити цей контроль обов'язковим перед злиттям через погоджений командний процес. Підстава: підтверджене падіння форматування на main 28.10. Це пропозиція; налаштування branch protection тут не змінювалися.
2. Для тривалих workflow PR застосувати concurrency із cancel-in-progress, щоб застарілі перевірки не займали спільні раннери. Підстава: у первинній таблиці видно черги; конкретну зміну та ефект треба вимірювати окремо, а не обіцяти наперед.
