# Lab10 — бонус №2: менше зайвих запусків на спільних раннерах

Авторка: Софія Мілевська (проєктувальниця покращень).

## Дія з плану покращень

**Проблема.** Більше половини комітів у `main` змінюють лише документацію (звіти, посилання на відео), але кожен такий коміт запускає CI Pipeline, Code Quality, Dependency Audit і Traceability. Ці запуски займають ті самі чотири раннери, що й CI решти команд курсу. Крім того, коли в pull request пушать кілька комітів поспіль, старі запуски цього PR продовжують виконуватися, хоча їхній результат уже нікому не потрібен.

**Першопричина (з даних).** За 28.10–18.11.2026 у `main` було 54 коміти з запусками CI: 29 із них (54%) змінювали лише `docs/`, `Labs/` або `*.md`. Ці 29 комітів дали 112 запусків workflow і 101 хвилину роботи раннерів ([before.json](./evidence/bonus2/before.json)).

**Що змінено** (`ci.yml`, `code-quality.yml`, `dependency-audit.yml`, `traceability.yml`):

1. `concurrency` з `cancel-in-progress` лише для pull request. Новий push у PR скасовує застарілий запуск того самого PR. Для push група містить SHA коміту, тому запуски на `main` ніколи не скасовуються і не замінюються один одним.
2. `paths-ignore` (`docs/**`, `Labs/**`, `**/*.md`) лише для `push`. Після злиття змін тільки в документації CI на `main` не запускається.

**Чому `paths-ignore` не додано для pull request.** На `main` діє правило з сімома обов'язковими перевірками. Якщо workflow не запускається для PR, обов'язкова перевірка залишається в стані «Expected — waiting» і PR неможливо злити. Тому PR із документацією і далі перевіряються, а економія досягається після злиття.

**Чому `traceability.yml` без `paths-ignore`.** Він перевіряє RTM у `docs/requirements/`, тобто зміни документації для нього значущі.

## Яку метрику покращує

Цільова метрика — **час виконання змін, частина «черга»**: менше зайвих запусків на спільних раннерах означає менше очікування вільного раннера для змін, які справді треба перевірити. Безпосередньо ефект вимірюється хвилинами раннерів, які займає `main`, бо черга залежить і від навантаження інших команд курсу.

**Ціна (аналіз парами).** Злиття лише з документацією більше не дають зеленого запуску на `main`, тож за визначенням лабораторної вони не рахуються як розгортання. Частота розгортань формально знизиться, хоча кількість змін коду не зміниться. У порівнянні «до/після» враховано лише коміти зі змінами в коді, тестах або конфігурації.
