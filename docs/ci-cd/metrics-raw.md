## Період і джерело

27.10–16.11.2026 включно, UTC: від `2026-10-27T00:00:00Z` до `2026-11-17T00:00:00Z` (верхня межа виключна). Вибір за `created_at` запуску. Це той самий період, що в [PR #268](https://github.com/ukma-fin-ssdm-2026/Rehab/pull/268) аналітикині DORA.

Використано незмінений [API-знімок колеги](./evidence/dora-auto-api-snapshot.json) з коміту [246850a](https://github.com/ukma-fin-ssdm-2026/Rehab/commit/246850ad875c2216e397efa013a7fa047dc8fb99), експортований 18.11.2026. Збір початкового API-знімка належить авторці PR #268; внесок ролі №1 у цьому пакеті — нормалізація історії, обчислення часових меж запусків, прив'язка кожного рядка до доказу й перевірка повноти. Список запусків додатково незалежно експортовано через GitHub API у main-ci-runs-api.json: усі 54 ID, SHA, статуси й номери спроб збігаються. Детальні jobs і перші коміти PR залишаються зі знімка колеги. Статуси зафіксовано на момент вихідного знімка.

## Вибірка і правила

- Враховано тільки workflow `CI Pipeline`, подію `push`, гілку `main`. Інші workflow та перевірки PR не включено; це обмеження вибірки, а не оцінка всіх перевірок репозиторію.
- 54 запуски, 54 різні SHA: 53 `completed/success`, 0 невдалих, 1 `queued`. Успішний CI на `main` — навчальне наближення розгортання.
- Черга, хв = (найраніший `jobs.started_at` − `run.created_at`) / 60.
- Виконання, хв = (найпізніший `jobs.completed_at` − найраніший `jobs.started_at`) / 60. Це тривалість інтервалу виконання всього запуску; паралельні jobs не підсумовуються, очікування наступних jobs усередині інтервалу входить у нього.
- «Завершення jobs» — останній `completed_at`. Окремо наведено `run.updated_at`, який колега використала як наближення завершення CI. Ці часові позначки можуть відрізнятися; `updated_at` не є спеціальним полем завершення.
- Перший коміт PR узято зі словника `first_commits` вихідного знімка; PR зіставлено за `merge_commit_sha == head_sha`. Дати комітів до 27.10 допустимі: період обмежує запуски CI.
- Для `queued` завершення, завершена черга і виконання не визначені: «—» не означає нуль. `run_started_at` не підмінює початок першого job.
- Значення в хвилинах округлено до 0,001; вихідні timestamps у JSON збережено до секунди. В усіх записах `run_attempt = 1`; повну історію попередніх спроб окремо не експортовано.

## Звірка з роллю №2

Кількість запусків і статуси збігаються з PR #268: 54 / 53 / 0 / 1. Це дає 53 / 3 = 17,67 успішних CI на тиждень (2,52 на день) і 0 / 53 = 0% невдалих завершених CI.

Колега у своєму звіті навела медіани черги й виконання **окремих jobs**; стовпці вище вимірюють **цілий запуск**. Це різні одиниці спостереження. Для Lead Time за точним завершенням jobs слід використовувати стовпець «Завершення jobs»; для відтворення наявного розрахунку PR #268 — `run.updated_at`. Докладна звірка та походження доказів — у [README доказів](./evidence/README.md).
