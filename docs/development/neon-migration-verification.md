# Онлайн-міграція PostgreSQL — частина Поліни для КТ-1

Перевірено 29.10.2026. Проєкт Neon Rehab `rough-lake-01450787`,
гілка `production` (`br-young-sunset-b9fxrv0z`), БД `neondb`, PostgreSQL 18.

## Міграція

Застосовано SQL, згенерований чинною Alembic-міграцією репозиторію:
`python -m alembic upgrade head --sql`. Пароль у SQL або Git не записується.
Перед застосуванням перевірені таблиці, колонки, FK, CHECK та унікальність
на ізольованій гілці Neon. В основній БД до міграції таблиць застосунку не було.

Міграцію виконано через підключений інструмент Neon, після підтвердження
Поліни. Термінальний запуск із паролем у команді не виконувався.
Створено `users`, `day_records`, `goals`, `alembic_version`;
версія `0001_initial`. Дві тимчасові гілки перевірки видалені.

## Реальна онлайн-перевірка

API: https://rehab-api-0na0.onrender.com. Виконано 25 перевірок без підмін
авторизації чи перерахунку. Використані лише синтетичні акаунти й записи.

- `/health`, `/ready`: 200.
- Реєстрація U1/U2: 201; вхід і `/me`: 200.
- Створення sober-запису: 201; повтор тієї самої дати: 409.
- Читання власного запису: 200; чужого запису/цілі: 404;
  календар U2 не містить записів U1.
- Ціль на 1 день після sober: досягнута; серія у статистиці — 1.
- PATCH на relapse: 200; серія — 0, relapse_days — 1,
  досягнення після корекції скасоване.
- Звичайний користувач не має доступу до admin API: 403.
- Вихід: 204; старий JWT для календаря: 401.
- Новий HTTP-клієнт після повторного входу читає той самий relapse-запис.

Незалежний SELECT через Neon після API-запитів підтвердив версію
`0001_initial`, 2 користувачів, 1 календарний запис та 1 ціль.
Тестові користувачі мають префікс email `kt1-polina-20261029164350-`
і домен `example.test`; ідентифікатори 1/2, запис 1, ціль 1.
Реальні персональні або медичні дані не вводилися. Очищення онлайн-БД не запускалося.

## Що ще не підтверджено

- Перезапуск саме Render API й читання даних після нього: потрібна спільна
  перевірка із Софією; новий HTTP-клієнт цього не замінює.
- Блокування користувача через справжній адмінський API: потрібен погоджений
  demo-admin. Права користувачів під час цієї перевірки не підвищувалися.
- Повний frontend-сценарій та iPhone/Safari: не перевірені цим API-прогоном.

Цей звіт підтверджує онлайн-міграцію та перелічені API-сценарії,
але не закриває всю командну КТ-1. Android не перевірявся.
