## Перевірені сценарії

- Реєстрація/вхід, справжній profile router та налаштування.
- Приєднання за кодом, календар і статистика підопічного лише для читання.
- Збереження зриву → одне повідомлення ментору; зміни статусу не дублюють його.
- Зрив без ментора позначається; пізніше приєднання не відтворює стару подію.
- Коментар ментора → приватне повідомлення підопічному → скарга з доказом.
- Схвалення скарги → доступ закрито, повторне приєднання заборонено, вхід працює.
- Виправлення запису на sober забороняє нову підтримку; вікно редагування 48 годин.
- Відкат помилки повідомлення скасовує календарний запис разом із подією.
- Конкурентні приєднання, взаємні скарги, job/зрив та коментарі без дублів.
- Справжній create_due_reminders підключений до internal job; outbox обробляє
  тестовий sender, повторний job не надсилає sent повторно.
- За відсутності Gmail поточні pending зберігаються, минулі pending/failed
  стають skipped, старі sending — unknown без повторного надсилання.
- Приватні routes вимагають JWT; messages у захищеній клієнтській навігації.
- Кнопка скарги передає notification_id, а форма завантажує власний коментар.

Автоматичні сценарії: `tests/test_calendar_relapse_notifications.py`,
`tests/test_kt_b_integration.py`, чинні тести менторства/скарг/профілю/
повідомлень/пошти та `frontend/tests/complaint-navigation.test.cjs`.

## Виправлення, підтверджені RED → GREEN

1. Календарний HTTP-запит не створював подію; тепер викликає emit_relapse_once
   після flush і перерахунку прогресу, перед єдиним commit.
2. Взаємні скарги й job/зрив могли deadlock-нути на users FOR UPDATE;
   узгоджено FOR NO KEY UPDATE, порядок users → mentorships → record/notification.
3. Перехід до скарги передавав інший параметр, і доказ не завантажувався;
   перевірено справжній onPress та погоджений notification_id.
4. Без Gmail не виконувалося очищення outbox; незалежний review виявив проблему,
   додано failing regression та незалежне від sender обслуговування черги.
5. Параметр 5 МіБ у тесті аватара перевищував Windows environment limit через
   PYTEST_CURRENT_TEST; короткі ids зберігають ту саму перевірку файлів.
