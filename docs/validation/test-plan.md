# Тест-план: «Рехаб» (Rehab)

## Обсяг

**Тестуємо:**
- Календар відміток (US-001): відмітка поточного дня, заборона вибору іншої дати
- Сповіщення ментора про зрив (US-002)
- Цілі тверезості та бейджі (US-003)
- Модерація скарг адміністратором (US-004)
- Порівняння серії з рекордом (US-005)
- Аналітика категорій тригерів (US-006)
- Редагування запису протягом 48 годин (US-007)
- Запити на наставництво (US-008)

**Свідомо НЕ тестуємо:** візуальний дизайн платіжні сервіси, повне кросплатформне UI-тестування, зовнішні інтеграції та функціональність, яка не входить до зазначених вимог.

- Усі тести плану зелені в CI
- Покриття Backend не нижче 95% (зараз 99%; поріг закріплюємо в CI через `--cov-fail-under=95` разом із `--cov-branch`)
- Немає відкритих критичних дефектів
- Усі FR з `rtm.md` мають щонайменше один виконаний тест
- Навантажувальний тест (`locust` або `k6`) виконано й p95 ≤ 500 мс при 100 користувачах

## Ризики

З цих місць починаємо таблицю:

1. **Модерація та блокування сесій (US-004)**: помилка дає користувачу доступ після блокування, найвища ціна.
2. **Сповіщення про зрив (US-002)**: ментор не дізнається вчасно про кризу підопічного.
3. **Межа 48 годин (US-007)**: класичне граничне значення, легко помилитися на ±1 годину.
4. **Рекорд і серія (US-005)** та підрахунок тверезих днів: помилки на межах періоду (раніше вже був дефект `count_sober_days()` на останньому дні).
5. **Необроблені гілки помилок:** три рядки без покриття (`main.py:86`, `models.py:86`, `routers/calendar.py:108`).

## Бонус: тести як специфікація для агента

- **Вимога:** `FR-007` — анонімний розподіл категорій тригерів за останні 30 днів.
- **Функція:** `calculate_trigger_distribution()` у `backend/app/services/statistics.py`.
- **Тести:** `tests/test_trigger_distribution.py` — параметризовані правила для часток категорій, включних меж періоду, пропуску тверезих і некатегоризованих записів, а також майбутньої дати звіту.
- **Послідовність:** спершу зафіксовано тестовий коміт `test: specify anonymous trigger distribution`; реалізацію додано наступним окремим комітом.
- **Використання ШІ:** ШІ згенерував тестові сценарії та реалізацію функції; один цикл генерації з подальшим ручним оглядом. Вручну перевірено склад періоду, відсутність персональних полів у відповіді та обробку порожньої вибірки.
- **Огляд ШІ-коду:** контрольний список і пояснення рішень наведено в `docs/validation/review-log.md`.
