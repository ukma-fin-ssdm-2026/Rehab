# Локальна перевірка менторства після спільної основи

Дата: 30 жовтня 2026 року. Це перевірка модуля Поліни локально, не звіт
про нову онлайн-версію або проходження всієї КТ-Б.

## Середовище

- Локальний Rehab; PostgreSQL 16 у Docker, окремі dev/test бази.
- Справжні FastAPI/JWT/SQL-модулі; новий router підключено до локального
  preview-app без зміни спільного main.py.
- Браузер із шириною 430 px. Це перевірка адаптивності, не реальний Safari
  на iPhone; iOS-перевірка залишається для спільного розгортання.
- Окремі синтетичні акаунти з доменом example.test. Коди, JWT і паролі
  не додаються до звіту. Міграції й дані Neon не змінювалися.

## Перевірено вручну

| Сценарій | Результат |
| --- | --- |
| Вхід у тестовий акаунт → підтримка | Власний код, пояснення доступу, немає ментора/підопічних |
| Введення коду іншого тестового користувача | Зв'язок створився відразу, підопічний з'явився у списку |
| Відкрити підопічного | Дозволений календар, контакти й статистика; лише читання |
| Історичний relapse-запис | Видно дату, статус, тригер, напій і коментар |
| День без запису | Показаний як тверезий у межах tracking-періоду |
| Перемикання all → month | Межі періоду й кількість тверезих днів змінюються правильно |
| Скасувати завершення | Зв'язок залишається активним |
| Підтвердити завершення | Підопічний зникає зі списку активних |
| Повторно ввести той самий код | Повідомлення про заборону повторного приєднання |
| Повторно відкрити прямий URL завершеного зв'язку | «Менторство завершено», приватні дані не показуються |

## Автоматизовані перевірки

`tests/test_mentorship_api.py`: справжні JWT, захист усіх маршрутів,
приватний код, нормалізація, ідемпотентність, заборона self/admin,
історичне завершення, незалежність пар, пагінація, співіснування ролей,
ізоляція чужих записів і відсутність write-доступу, read-only статистика,
конкуренція менторів, взаємне одночасне приєднання та відсутність commit
у сервісі.

Перевірка взаємного приєднання синхронізує справжні SQL INSERT двох
сесій. Із FOR UPDATE на users тест відтворив DeadlockDetected; із
FOR NO KEY UPDATE пройшов. Це регресійний тест реальної гонки.

`frontend/tests/mentorship.test.cjs`: реальний спільний API-client,
Bearer JWT, шляхи/параметри, signal скасування, валідація коду/ID,
календар високосного лютого й захист прямого маршруту.

`frontend/tests/support-lifecycle.test.cjs`: приєднання, завершення та
пагінація, які завершуються після виходу з вкладки. Review знайшов
зависання busy=true; усі три тести спочатку відтворили дефект, після
прив'язки pending-операції до власника й узгодження стану на focus пройшли.

Фінальний локальний прогін: 334 серверні тести й 64 клієнтські тести
пройшли; TypeScript та web export пройшли. Лінт — без помилок, зі старими
двома попередженнями адмінки, наведеними нижче.

Повні результати остаточного SHA наведені в PR. Не підміняти ними
факт проходження CI або ще не виконаної онлайн-перевірки.

## Залежності та відомі попередження

- Реєстрація router/OpenAPI — Софія; root layout/ProfileProvider — Анастасія.
- Повідомлення/коментарі — Марія, календарна подія підключається разом із
  готовим модулем. Форма скарги — Софія; callback уже передбачений.
- Чинний frontend lint має два попередження set-state-in-effect у старих
  admin/analytics.tsx та admin/users.tsx. Ці файли модулем не змінюються.
- Після відвідування чинної home.tsx локальна dev-версія повідомляє
  `Unexpected text node: .`: існуючий error='' використаний як `error &&`
  поза Text. Повідомлення спостерігалося до переходу на нову підтримку;
  передати Марії для її користувацьких екранів. Не вважати dev-console
  повністю чистою. На прямому завантаженні нового екрана проблема не
  відтворилася без монтування home.
