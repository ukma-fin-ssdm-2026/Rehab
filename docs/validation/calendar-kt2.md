# Календар Поліни — реалізація та приймання КТ2

Локальні перевірки перед PR №192: 2026-10-29. Гілка: `codex/kt2-calendar-ui`; початкова база: `36c59bf`,
перед PR оновлено поверх `8c5c012` зі змінами життєвого циклу JWT Анастасії.
Реалізацію підготовлено за допомогою ChatGPT за розділами 4 і 7 командного ТЗ.

## Реалізовано

- Типізований календарний клієнт через спільний `apiRequest` і поточний JWT.
- Створення sober/relapse, необов'язкові тригер та напої, перевірка дати,
  додатного цілого об'єму та коментаря до 2000 символів.
- Деталі `/entry/{record_id}`: статус, тригер, напої, коментар, час створення.
- PATCH лише статусу й тригера; блокування кнопки після 48 годин,
  обробка серверного `EDIT_WINDOW_EXPIRED`. Напої та дата не редагуються.
- Оновлення календаря при поверненні фокуса; повтор запиту після помилки.
- Дата й початок відстеження надходять з `/auth/me`.
- При перемиканні місяця вибирається перший день нового місяця.
- Навігація очікує відновлення сесії, зберігаючи прямий URL деталей.

- `python -m pytest -q --disable-warnings`: 281 passed, 2 warnings.
- Окремий календарний прогін: 47 passed (PostgreSQL API, auth, деталі,
  регресії календаря та інтеграційний перерахунок прогресу).
- `npm run test:api`: 15 passed, включно з 7 календарними перевірками
  та новими перевірками життєвого циклу JWT Анастасії.
  Нові правила/API спочатку перевірені падаючими тестами; переходи місяця
  й очікування restore теж мають окремі тести RED → GREEN.
  Після оновлення develop старий тест завершення сесії уточнено: він
  встановлює прострочений JWT, оскільки без токена немає активної сесії
  для завершення. Реалізацію API-клієнта Анастасії не змінено.
- TypeScript та вебекспорт проходять. Lint: 0 помилок, 5 наявних попереджень
  в інших екранах (home/goals/statistics/admin), не змінених цим PR.
- Незалежний огляд знайшов втрату URL під час restore і стару вибрану дату
  при зміні місяця; обидва виправлені та повторно перевірені.

## Браузерна перевірка

Локальна production-збірка, локальний FastAPI, PostgreSQL Compose dev.
Використаний окремий синтетичний користувач; персональні акаунти не змінювалися.
Підготовлений окремий запис із часом створення понад 48 годин тому.

Підтверджено через інтерфейс:

- календар відрізняє розраховану тверезість від збереженого запису;
- вибраний день передається у форму, дата обмежена серверним діапазоном;
- дробовий об'єм відхиляється зрозумілим повідомленням;
- relapse із тригером, 330 мл пива та коментарем зберігається, деталі правильні;
- reload деталей з чинною сесією залишає `/entry/{id}` і завантажує дані;
- PATCH на sober очищує напої й тригер, коментар зберігається;
- повернення до календаря показує новий стан без ручного reload;
- прострочений запис показує пояснення, кнопка має `aria-disabled=true`;
- наступний місяць вибирає перше число, не пропонує створення майбутнього запису;
- деталі перевірені при ширині 430 px без виходу вмісту за екран.

Початковий smoke до очищення Metro cache використовував публічний API з
синтетичним акаунтом. Остаточний прогін виконано з підтвердженою локальною
адресою API в збірці. Це не перевірка нової версії на реальному iPhone.
