# Бонус №1 Lab 07: автоматична перевірка простежуваності

## Реалізація та запуск

[PR #163](https://github.com/ukma-fin-ssdm-2026/Rehab/pull/163) додає
`scripts/check_traceability.py`, модульні тести та workflow
`.github/workflows/traceability.yml`. Команди доступні після включення #163
або в його гілці `feature/lab07-traceability-gate`:

```shell
python -m unittest discover -s scripts -p 'test_check_traceability.py' -v
python scripts/check_traceability.py
```

Додаткових пакетів для цих двох команд не потрібно. Workflow запускається
для pull request до `main` та push у `main`.

Валідатор зіставляє визначення FR/NFR у `docs/requirements/requirements.md`,
таблицю кейсів у `docs/validation/test-plan.md` та розділ
«Простежуваність тест-кейсів Лаб 7» у `docs/requirements/rtm.md`.
Поточний формат передбачає один ID вимоги на кейс. Старі позначення
`Test-01` тощо в таблиці історій користувачів не входять у цю перевірку.

Відсутні вимоги чи кейси, невідомі ID, дублікати коректних рядків і
суперечливі зв'язки спричиняють ненульовий код завершення.
Це перевірка запланованого покриття: вона не підтверджує виконання кейсів,
відповідність їхнього змісту вимогам або заповнення власників.

## Історичний стан на час підготовки звіту

У 31 кейсі тест-плану ще стоїть шаблон `<ім'я>`. Відповідальна учасниця
має заповнити власників окремим PR; імена не призначаються автоматично.
Результати фактичного виконання системних, приймальних та нефункціональних
сценаріїв перевіряються окремо за критеріями виходу тест-плану.

Для злиття #163 та цього документа потрібне схвалення іншої учасниці
за TeamCharter. Під час підготовки цих результатів `main` не змінювався
напряму, merge не виконувався.
