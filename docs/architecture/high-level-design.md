# Високорівнева архітектура (High-Level Design) системи "Рехаб"

## 1. Архітектурний стиль

Система "Рехаб" побудована за клієнт-серверною моделлю з використанням архітектурного стилю **Layered Monolith** на стороні сервера. 

Цей вибір зумовлений розміром команди, стислими термінами розробки MVP та відсутністю необхідності в складному розподіленому розгортанні. Монолітна архітектура забезпечує простоту локального тестування, легкість в обслуговуванні транзакцій та зрозумілий поділ відповідальності всередині коду (контролери, бізнес-логіка, доступ до даних), уникаючи накладних витрат мікросервісної архітектури.

## 2. Основні компоненти системи

1. **Клієнтський застосунок (Web Frontend):** 
   Інтерфейс користувача, який відповідає за відображення календаря відміток, статистики, цілей та сторінки менторства. Відправляє дії користувача на сервер для обробки.
2. **REST API Сервер (Backend):** 
   Центральний вузол бізнес-логіки. Приймає запити від клієнта, перевіряє права доступу (аутентифікація), виконує розрахунки (наприклад, обчислення серії успішних днів - streak) та управляє даними.
3. **База даних (Database - PostgreSQL):** 
   Реляційне сховище даних. Зберігає профілі користувачів, історію відміток у календарі, зв'язки між менторами та підопічними, а також налаштування цілей.

## 3. Інтерфейси взаємодії

* **Frontend ↔ Backend (Клієнт - Сервер):** Взаємодія відбувається через мережу Інтернет за протоколом HTTP/HTTPS. Сервер надає REST API, обмін даними здійснюється у форматі JSON. Для авторизації запитів використовується передача JWT-токена в заголовках HTTP.
* **Backend ↔ Database (Сервер - БД):** Взаємодія відбувається у внутрішній захищеній мережі через драйвер СУБД за допомогою SQL-запитів. Сервер використовує механізми пулу з'єднань (Connection Pool) для оптимізації навантаження.
