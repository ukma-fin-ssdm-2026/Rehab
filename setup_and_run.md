# Rehab — налаштування та запуск застосунку

**Стан інструкції:** 15 жовтня 2026 року. Перевірено локальний запуск **FastAPI + Expo Web** після злиття Backend і Frontend у `feature/rehab-prototype`.

**Для кого:** учасники команди, які вперше завантажують проєкт або хочуть відтворити демонстраційний сценарій.

**Операційна система команд:** Windows, PowerShell (термінал VS Code).

**Звіт про виконану роботу:** [PROGRESS.md](docs/code-quality/progress.md).

> **Найважливіше.** Репозиторій розділено на **`backend/`** і **`frontend/`**. Старий FastAPI з `src/api/` перенесено й адаптовано до `backend/app/`. Тепер сервер слід запускати модулем `backend.app.main:app` із кореня `Rehab/`. Frontend — окремий Expo-проєкт у `frontend/`. Для прототипу використовуйте інтеграційну гілку `feature/rehab-prototype`, не `main`.

## 4. Термінал № 1: налаштування Python і запуск FastAPI

**Усі наведені команди виконуються з кореня `Rehab/`.**

### 4.1. Віртуальне середовище (одноразово)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
```

Якщо `.venv` уже існує, повторно створювати його не потрібно. Достатньо:

```powershell
.\.venv\Scripts\Activate.ps1
```

Якщо PowerShell не дозволяє виконувати `Activate.ps1`, можна обійти активацію, викликаючи `.\.venv\Scripts\python.exe` безпосередньо з кореня проєкту. Не потрібно змінювати системні правила безпеки лише заради запуску.

### 4.2. Запуск сервера

```powershell
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Очікуване повідомлення:

```text
Uvicorn running on http://127.0.0.1:8000
Application startup complete.
```

Відкрийте:

- Swagger UI: http://127.0.0.1:8000/docs
- OpenAPI JSON: http://127.0.0.1:8000/openapi.json

**Не закривайте термінал № 1.** Коли ви зупините процес, Frontend втратить зв'язок із сервером.

### 4.3. Швидка перевірка API

У Swagger знайдіть:

- `GET /api/v1/calendar/entries`
- `POST /api/v1/calendar/entries`
- `GET /api/v1/statistics`
- наявні маршрути `/api/v1/goals`

Для захищених запитів натисніть **Authorize** і введіть демонстраційний Bearer-токен `user-42` (якщо форма Swagger сама додає `Bearer`, не дублюйте цей префікс).

Виконайте `GET /api/v1/calendar/entries` і `GET /api/v1/statistics?period=all`. Очікуваний статус для правильно авторизованого запиту — **200**.

> `user-42` — тестовий ідентифікатор, не реальна JWT-авторизація. Не використовуйте особисті паролі або секрети для цієї демонстрації.

## 5. Термінал № 2: встановлення залежностей Frontend

Відкрийте новий термінал у VS Code. З кореня `Rehab/` виконайте:

```powershell
cd frontend
npm ci
```

`npm ci` бере узгоджені версії пакетів із `package-lock.json`, тому для командної перевірки він кращий за довільне перевстановлення залежностей.

**Фактично перевірено:** команда успішно встановила 569 пакетів. Водночас npm повідомив про **28 вразливостей (10 moderate, 18 high)** і застарілу версію `uuid`. Це не завадило локальному запуску, але означає, що питання безпеки залежностей ще не закрите. Не запускайте `npm audit fix --force` без узгодження — можуть виникнути несумісності з Expo.

## 6. Як налаштувати Frontend API

Frontend має звертатися до FastAPI на порту `8000`, а не до іншого старого сервера.

У локальному файлі **`frontend/.env.local`** (створіть його, якщо потрібне власне налаштування) для Expo Web на одному комп'ютері використовувався варіант:

```dotenv
EXPO_PUBLIC_API_URL=http://127.0.0.1:8000
```

У старішій чернетці API-контракту зустрічався інший варіант — URL із доданим `/api/v1`. У фактичному Frontend після інтеграції є **`frontend/src/config/api.ts`**, тож не варто сліпо додавати `/api/v1` удруге. Якщо API-клієнт сам формує шляхи `/api/v1/...`, наведена адреса без суфікса є правильною. Якщо спосіб формування URL колись зміниться, звіряйте файл `src/config/api.ts` і реальні запити в Network браузера.

**Важливо:** для перевіреного запуску Expo Web на цій машині обидві адреси `http://localhost:8081` та `http://127.0.0.1:8081` дозволені CORS; сервер слухає `127.0.0.1:8000`. Якщо не можете підключитися, перевірте правильну адресу середовища і перезапустіть Expo після зміни `.env.local`.

`EXPO_PUBLIC_*` не є місцем для секретів: такі значення доступні в клієнтському застосунку. У цей файл не потрібно вставляти реальні токени або паролі.

## 7. Термінал № 2: запуск Expo Web

Перебуваючи в `Rehab/frontend/`, виконайте:

```powershell
npx expo start --web
```

Дочекайтесь повідомлення Expo про доступність Web-застосунку. Зазвичай він відкривається тут:

**http://localhost:8081**

Якщо Expo надрукував інший порт, використовуйте фактичну адресу, а не припускайте, що це обов'язково `8081`. За іншого порту треба окремо перевірити налаштування CORS сервера.

Тепер мають бути відкриті два процеси одночасно:

| Термінал | Що працює | Адреса |
|---|---|---|
| № 1 (корінь Rehab) | FastAPI | `http://127.0.0.1:8000` |
| № 2 (`frontend/`) | Expo Web | `http://localhost:8081` (або адреса з виводу Expo) |

Для зупинки кожного процесу натисніть `Ctrl+C` у відповідному терміналі.

## 8. Як перевірити працездатність готового прототипу

### 8.1. Основний наскрізний сценарій

1. Відкрийте Web-застосунок Rehab, виконайте демонстраційний вхід.
2. Перейдіть на Головну.
3. Відкрийте Додати запис.
4. Виберіть дату, на яку в поточного демокористувача ще немає запису.
5. Вкажіть статус `relapse`, додайте щонайменше два напої, наприклад `beer` (330 мл) та `wine` (150 мл); за потреби виберіть тригер і додайте коментар.
6. Збережіть запис. У Network браузера `POST /api/v1/calendar/entries` за коректного запиту має повернути **201**.
7. Відкрийте Календар і переконайтеся, що вибраний день змінив статус.
8. Відкрийте Статистику та Цілі; переконайтеся, що значення пов'язані зі збереженим записом. Звірте також показники на Головній.
9. Перейдіть до всіх інших вкладок та профільних заглушок; перевірте повернення й навігацію.

**Саме цей головний сценарій, за повідомленням команди, уже працював після merge.** Якщо ви тестуєте повторно після перезапуску сервера, початкові дані можуть відрізнятися через in-memory сховище.

### 8.2. Узгоджений формат запису

```http
POST /api/v1/calendar/entries
Authorization: Bearer user-42
Content-Type: application/json
```

```json
{
  "date": "2026-10-15",
  "status": "relapse",
  "trigger_category": "social",
  "drinks": [
    {"type": "beer", "volume_ml": 330},
    {"type": "wine", "volume_ml": 150}
  ],
  "comment": "Демонстраційний запис"
}
```

Назви полів саме такі: `date`, `status`, `trigger_category`, `drinks`, `type`, `volume_ml`, `comment`.

- `date` — `YYYY-MM-DD`, не майбутня дата;
- `status` — `sober` чи `relapse`;
- `trigger_category` — необов'язкове `stress`, `holiday`, `social`, `other` (для `relapse`);
- `drinks` — масив напоїв (`beer`, `wine`, `spirits`, `cocktail`, `other`);
- `volume_ml` — додатне ціле число, не рядок;
- `comment` — необов'язковий текст/`null`;
- для `sober` не передавайте напої;
- повторний POST на ту саму дату — `409 Conflict`.

Приклад із конкретною датою демонстраційний — перш ніж використовувати його, переконайтеся, що дата дозволена й не зайнята.

### 8.3. Маршрути й заглушки

У прототипі **16 продуктових маршрутів**: `login`, `register`, `onboarding`, `home`, `add-entry`, `calendar`, `goals`, `statistics`, `profile`, `friends-support` та 6 окремих сторінок `placeholders/`:

```text
edit-profile
change-password
notifications
notification-vibe
help
privacy
```

Заглушками є **вкладка «Друзі / підтримка»** та **шість перелічених екранів профілю**. Демонстраційними без реального серверного акаунта є також **Вхід, Реєстрація, Onboarding**. Натискання кнопок і переходи можуть працювати — але справжні зміни пароля, push, чати та зміна профілю не виконуються. Це задумано для першої версії, а не збій запуску.

## 10. Необов'язковий запуск на фізичному телефоні

> **Статус:** цей сценарій наведено як орієнтир для окремої перевірки; у цьому звіті підтверджений саме Expo **Web**, а повний запуск на фізичному телефоні ще не зафіксований як успішний.

1. Підключіть телефон і комп'ютер до однієї локальної мережі.
2. У PowerShell комп'ютера, який запускає FastAPI, виконайте `ipconfig` і знайдіть локальний IPv4 (наприклад, `192.168.1.105` — лише приклад).
3. Замість локального запуску `127.0.0.1` використайте:

   ```powershell
   python -m uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
   ```

4. У `frontend/.env.local` впишіть **IP комп'ютера з FastAPI**, наприклад:

   ```dotenv
   EXPO_PUBLIC_API_URL=http://192.168.1.105:8000
   ```

5. Перезапустіть Expo після зміни адреси. Якщо поточна конфігурація сумісна з Expo Go, запустіть `npx expo start` та відкрийте проєкт з QR-коду.
6. Переконайтеся, що **з телефона** відкривається `http://192.168.1.105:8000/docs`. За потреби перевірте брандмауер і дозволені мережеві запити.

**Чому не `127.0.0.1`:** на телефоні ця адреса вказує на сам телефон, а не на комп'ютер. **Чому не `0.0.0.0` у `.env.local`:** це лише адреса прослуховування сервера, не мережевий URL клієнта. Режим `0.0.0.0` використовуйте тільки в довіреній мережі. Якщо для native-запитів потрібна інша конфігурація мережі, звірте її з розробницею Frontend.

## 11. Часті проблеми

| Симптом | Що перевірити |
|---|---|
| `404` на `/api/v1/statistics` | Чи працюєте у `feature/rehab-prototype`, чи сервер запущено через `backend.app.main:app`; маршрут має бути в Swagger |
| `OPTIONS → 400` і `Failed to fetch` під час POST | Перевірте Origin Expo Web (`localhost:8081` або `127.0.0.1:8081`), адресу API, актуальний Backend і CORS; старий код міг не дозволяти POST |
| `401 Unauthorized` | Для захищених маршрутів потрібен `Authorization: Bearer user-42` |
| `409 Conflict` | На обрану дату вже є запис; виберіть іншу дату |
| `422 Unprocessable Entity` | Перевірте JSON: допустиму дату, статус, тригер, `volume_ml` як додатне ціле число; при `sober` не можна передавати напої |
| Expo відкривається, але дані не завантажуються | Чи працює FastAPI, чи коректна адреса в `.env.local`, чи не подвоєно `/api/v1`, чи перезапущено Expo після зміни налаштувань |
| Порт 8000 або 8081 зайнятий | Закрийте зайвий процес або узгоджено змініть порт; при зміні origin браузера може знадобитися CORS-коригування |
| Дані «зникли» після перезапуску | Це очікувана поведінка демонстраційного in-memory сховища |
| PowerShell блокує активацію `.venv` | Використайте `.\.venv\Scripts\python.exe` напряму або локальні налаштування за правилами ПК |
| npm показує вразливості | Зафіксовано 28 попереджень; проаналізуйте `npm audit`, не запускайте `--force` без узгодження |

## 12. Що не повинні очікувати учасники від поточного прототипу

У застосунку **немає production-авторизації й реєстрації, постійної бази даних, реальних акаунтів друзів, чатів, сповіщень менторам, push-повідомлень, налаштування приватності, зміни пароля чи інтеграції з Apple Watch/Mi Band**. Відповідні екрани або є локальними демонстраційними сценаріями, або відкривають окремі заглушки. Це погоджені обмеження. Не додавайте ці функції самостійно без командного рішення.
