# Rehab — налаштування та запуск застосунку

**Актуалізовано:** 28 жовтня 2026 року для інтегрованого прототипу в гілці `main`.

**Статус перевірки:** попередній локальний запуск FastAPI + Expo Web був задокументований 15 жовтня 2026 року. Ця редакція виправляє застарілі шляхи та інструкції. **Повторний запуск із чистого клонування після цієї редакції необхідно виконати**; він не позначається як успішний без фактичної перевірки.

**Для кого:** учасники команди, викладач і будь-хто, хто хоче відтворити поточний демонстраційний сценарій.

**Приклади команд:** Windows / PowerShell у терміналі VS Code. Для macOS і Linux відрізняються насамперед команди активації віртуального середовища.

## 3. Структура проєкту та робочі каталоги

Нижче наведено основні шляхи, потрібні для запуску (це не повний перелік файлів репозиторію):

```text
Rehab/
├── backend/
│   └── app/
│       ├── main.py                 # застосунок FastAPI
│       ├── routers/               # API-маршрути
│       ├── services/              # бізнес-логіка
│       ├── models.py              # моделі даних
│       └── stubs.py               # застаріле in-memory сховище прототипу; маршрути його не використовують
├── frontend/
│   ├── src/
│   │   ├── app/                   # екрани Expo Router
│   │   └── config/api.ts          # конфігурація API-клієнта
│   ├── package.json
│   └── package-lock.json
├── tests/                         # Python-тести
├── docs/                          # документація вимог, архітектури, API й тестів
├── Labs/                          # матеріали лабораторних та посилання на відео
├── requirements.txt               # Python-залежності: саме в корені
├── setup_and_run.md               # ця інструкція
└── README.md
```

**Важливо:** встановлення Python-залежностей виконується з **кореневого `requirements.txt`**. Шлях `backend/requirements.txt` у попередній редакції інструкції був помилковим.

## 5. Термінал № 2: залежності Frontend

Відкрийте новий термінал у VS Code. Із кореня `Rehab/` виконайте:

```powershell
cd frontend
npm ci
```

`npm ci` відтворює залежності за `package-lock.json`. Якщо залежності не встановлюються, перевірте версію Node.js та діагностику npm; не змінюйте lock-файл без командного узгодження.

У попередньому локальному запуску npm повідомляв про вразливості залежностей. **Їхня кількість не є актуальним результатом перевірки станом на 28 жовтня**. За потреби запустіть `npm audit` і задокументуйте фактичний результат. Не запускайте `npm audit fix --force` без узгодження з командою — це може зламати сумісність з Expo.

## 6. Налаштування адреси Backend у Frontend

Для Expo Web на тому самому комп'ютері створіть за потреби `frontend/.env.local` з таким вмістом:

```dotenv
EXPO_PUBLIC_API_URL=http://127.0.0.1:8000
```

**Не додавайте `/api/v1` до цього URL автоматично.** Перед зміною перевірте, як `frontend/src/config/api.ts` формує кінцеві шляхи: якщо він сам додає `/api/v1/...`, суфікс у змінній середовища призведе до дублювання.

Після зміни `.env.local` **перезапустіть Expo**. Змінні `EXPO_PUBLIC_*` стають доступними в клієнтському коді — не кладіть туди токени, паролі чи інші секрети.

Для Expo Web у браузері перевіряйте відповідність між Frontend origin (зазвичай `http://localhost:8081`), адресою API та дозволеними CORS origins у FastAPI. Якщо Expo відкривається на іншому порту, потрібна окрема перевірка CORS.

### 8.2. Приклад JSON-запиту до календаря

Заголовки:

```http
POST /api/v1/calendar/entries
Authorization: Bearer <access_token з POST /api/v1/auth/login>
Content-Type: application/json
```

Приклад тіла запиту (**дата умовна: замініть її на допустиму, не зайняту дату**):

```json
{
  "date": "2026-10-27",
  "status": "relapse",
  "trigger_category": "social",
  "drinks": [
    {"type": "beer", "volume_ml": 330},
    {"type": "wine", "volume_ml": 150}
  ],
  "comment": "Демонстраційний запис"
}
```

Основні правила для наведеного API-контракту:

- `date` — формат `YYYY-MM-DD`, без майбутніх дат;
- `status` — `sober` або `relapse`;
- `trigger_category` — необов'язковий `stress`, `holiday`, `social` або `other` для `relapse`;
- `drinks` — масив із `type` (`beer`, `wine`, `spirits`, `cocktail`, `other`) та `volume_ml` (додатне ціле число);
- `comment` — необов'язковий текст або `null`;
- для `sober` не передавайте напої;
- повторне створення запису на вже зайняту дату може повертати `409 Conflict`.

**Актуальні схеми, обов'язковість полів та відповіді перевіряйте у Swagger запущеного Backend**, оскільки реалізація може змінитися після злиття PR.

## 10. Необов'язковий запуск на фізичному телефоні

> **Статус:** це інструкція для додаткової перевірки. Працездатність поточного застосунку в Expo Go на фізичному телефоні **не підтверджується цим документом**; основний локальний сценарій — Expo Web.

1. Підключіть телефон і комп'ютер до однієї **довіреної** локальної мережі.
2. Виконайте `ipconfig` і знайдіть локальну IPv4-адресу комп'ютера (наприклад, `192.168.1.105`).
3. Із кореня `Rehab/` запустіть Backend, доступний у локальній мережі:

   ```powershell
   python -m uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
   ```

4. У `frontend/.env.local` установіть реальну адресу комп'ютера:

   ```dotenv
   EXPO_PUBLIC_API_URL=http://192.168.1.105:8000
   ```

5. Перезапустіть Expo (`npx expo start`) і за сумісності з поточною версією Expo Go спробуйте відкрити застосунок з QR-коду.
6. Із браузера **телефона** перевірте `http://192.168.1.105:8000/docs` (підставте свою адресу). За потреби перевірте брандмауер і мережеву доступність.

`127.0.0.1` на телефоні означає **сам телефон**, а `0.0.0.0` — адреса прослуховування сервера, **не** URL для клієнта. У цьому режимі не передавайте реальні дані: авторизація в прототипі демонстраційна.

## 11. Типові проблеми

| Симптом | Що перевірити |
|---|---|
| `No such file: backend/requirements.txt` | Використовуйте **`python -m pip install -r requirements.txt`** з кореня `Rehab/` |
| `ModuleNotFoundError` під час запуску Uvicorn | Чи відкрито корінь `Rehab/`, чи активоване правильне `.venv`, чи встановлені залежності |
